## 基本原則

このプロジェクトでは以下の原則に基づいて開発を行います:

### 1. 型安全性

- TypeScript の型システムを最大限活用し、実行時エラーを最小限に抑えます
- `any` 型の使用は避け、明確な型定義を行います
- フロントエンドとバックエンドで共通の型定義を `@repo/domains` で管理します

### 2. 可読性とメンテナンス性

- 変数名、関数名、コンポーネント名は意味が明確になるように付けます
- コードの構造を整理し、適切なインデントを使用します
- マジックナンバーは避け、定数として定義します
- JSDoc コメントを使用し、IDE のインテリセンスを向上させます

### 3. テスタビリティ

- ユニットテストを記述しやすい構造にします
- 依存関係を注入し、疎結合な設計を心がけます
- 重要なビジネスロジックには必ずテストを記述します

### 4. セキュリティ

- 入力のバリデーションを必ず行います
- 認証・認可を適切に実装します
- センシティブな情報はログに出力しません
- 環境変数で機密情報を管理します

### 5. パフォーマンス

- 不必要な再レンダリングを避けます
- データベースクエリを最適化します
- 適切なキャッシュ戦略を採用します

## コードフォーマット

本プロジェクトでは **Biome** を使用してコードのフォーマットとリンティングを行います。

```bash
# すべてのコードをフォーマット
pnpm biome:format

# すべてのコードをチェック
pnpm biome:check

# 自動修正
pnpm biome:fix
```
